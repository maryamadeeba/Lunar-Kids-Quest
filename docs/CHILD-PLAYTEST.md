# Later child playtest protocol

Status: prepared; no participants or results recorded.

## Set up

Use a willing child, a parent/guardian’s permission and an adult facilitator. Let the child stop at any time. Use an anonymous session code in your own records; do not enter names, contact details, recordings or identifying quotes. Record age band and device, not a birth date.

Open the game alongside the facilitator page at `#playtest`. Keep the observer page open. Each task has a timer, an outcome, an assistance level and a note field. Save deliberately on the device, and download an anonymous JSON copy if useful. Start with a new anonymous observation record for each participant; the tool keeps a single saved local draft. Download it, then use New blank session. The saved draft is replaced only when Save is pressed.

Say: “We’re testing the game, not you. You can try anything. Tell me what you notice.” Avoid teaching the expected answer before observing the child. Repeat the same prompt before giving progressively more help. Record any help honestly.

## Tasks

| Task | Neutral prompt | Record |
| --- | --- | --- |
| First practice action | Can you help our crew make some air? | Time to first useful action; whether air, water and battery changes were noticed. |
| Flashcard controls | What can you discover on this card? | Finds Flip, returns to picture, finds Next; reading/voice assistance. |
| Moon home | Where would you build? Show me why. | Benefit and drawback in the child’s own words. |
| Limited power | Can all the machines run at once? | Notices the limit, turns something off, explains what competes for power. |
| Math | Show me how you counted these cells. | Uses visual cells, arithmetic strategy, confusion after a wrong answer, assistance. |
| Delayed harvest | When will these lamps help us? | Distinguishes resource costs now from food later. |
| Shelter practice | Show me a safer place for everyone. | All three crew moved without rushing; controls understood before the real countdown. |
| Final understanding | Why can’t our astronauts do everything they want? | Unprompted explanation of limited resources and trade-offs. |

Targets from the product brief: a useful interaction within one minute, a competing-needs decision within three minutes, then explanations of power sharing, delayed food and safety versus science. These are targets to observe, not outcomes to assume.

## Per-task record

- Outcome: not observed / completed independently / completed with help / stopped.
- Help: none / prompt repeated / hint / adult demonstrated or took over.
- Actual elapsed time, if observed.
- What the child tried, where they hesitated and what they said (anonymous).
- Reading, tap-target, animation or terminology difficulty.

## Review after the session

Ask what the child enjoyed and what felt confusing. Do not turn the conversation into a graded test. Compare repeated patterns across participants: missed controls, cost/gain confusion, counting strategies and explanations. A single successful session does not establish educational effectiveness. Prioritize issues that block independent play, then re-test the changed interaction with another willing participant.

The in-app draft is a facilitator worksheet, not automatic analytics. It cannot certify that a child understood a concept. Real observation and subsequent design changes are still required.
